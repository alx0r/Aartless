Everything required to release, verify, and grow the first public instance — technical specs, legal bindings, architecture, roadmap, and founding team.

Erebus White Paper Roadmap Verification Team

Abstract

Forever Format™ is a minimal, citable, AI-readable protocol for living documents. This release package documents the full technical stack, legal constraints, roadmap, and community process for v1.2.0 — Codename: Erebus. Designed for longevity, auditability, and interoperable AI collaboration.

Technical Specification

Core Format

Single-file HTML template with inline CSS and semantic sections. Required sections and metadata are declared in the YAML front-matter comment and the JSON-LD block. Files must be <100KB when empty of large binary assets. Use git for versioning; embed SHA256 for releases.

Metadata Schema

YAML front-matter (commented):


---

title: "..." author: "..." date: "YYYY-MM-DD" version: "v1.2.0" provenance: repo: "https://github.com/.." commit: ""

JSON-LD: {"@context":"https://schema.org","@type":["CreativeWork","TechArticle"]...}

Integrity & Verification

Each release must publish:

  • Git commit SHA
  • SHA256 of the HTML file
  • Optional PGP or DID signature for author identity
  • Public mirror URLs and archive location (IPFS/gov archive)

Architecture Overview

The Forever Format ecosystem is modular — each document is an independent node that participates in a federated net. Key subsystems:

  1. Erebus Engine — Core single-file spec and format validator.
  2. Mnemosyne Graph — Cross-document linking, ontologies, and version recall.
  3. Prometheus Federation — Agent orchestration, co-authoring, and synthesis pipelines.
  4. Lethe Entropy — Revision, redaction, and ethical forgetting.
  5. Helios Verification — Public mirrors, signature validation, and ledger anchoring.

Data Model

Stores small artifacts inline, larger datasets via pointers (IPFS, git-lfs). All pointers must include a content hash. Prefer declarative over procedural storage.

Release Roadmap

Detailed phase breakdown and mythic rationale are included. (See Roadmap supplement: Erebus → Mnemosyne → Prometheus → Lethe → Helios.)

Phase I — Erebus (Q4 2025)

Deliverables: core template, validator, sample docs, verification script, release SHA. Validators: CLI tool to verify schema & hash.

Phase II — Mnemosyne (Q1 2026)

Deliverables: graph schema, linking primitives, citation crawler, memory API.

Phase III — Prometheus (Q3 2026)

Deliverables: federation APIs, agent SDKs, provenance ledger prototypes.

Phase IV — Lethe (Q1 2027)

Deliverables: self-revision engine, redaction protocols, legal templates for revision requests.

Phase V — Helios (2027–)

Deliverables: public intelligence network, mirror network, audit consortium.

Emerging Technology — AR & Accessibility

Short-term and medium-term goals for integrating AR wearables and accessibility tech with Forever Format documents.

  • Artemis: AR document viewers and overlays for live annotation.
  • Hephaestus: hardware-level accessibility, haptics, and low-power wearable integration.
  • Hermes: networked collaboration for shared AR sessions and verification overlays.
  • Athena: AI-driven cognitive assistance tuned for accessibility.
  • Apollo: public deployment and SDKs for community content.

Accessibility Requirements

  1. WCAG 2.1 AA baseline for document content.
  2. ARIA roles for semantic sections and dynamic content.
  3. Keyboard-first navigability and screen-reader friendly markup.
  4. High-contrast and user-adjustable typography.

Provenance & Verification

Publishing checklist (release):

  1. Commit to GitHub: tag release `v1.2.0-erebus-doc`
  2. Compute SHA256 and store in release notes
  3. Sign artifact with PGP and optionally anchor to DID
  4. Mirror to IPFS and a public archive
  5. Run validator; publish validation report

Verification Node Spec (minimal)

Node:

fetch(url)

compute sha256(file)

compare to release_sha

fetch signature

verify signature(pubkey)

report status (ok|mismatch|unsigned)
